DocQuery is a document question-answering application that allows users to upload documents and ask questions about their content.

The project uses document loading, text chunking, sentence embeddings, vector similarity search, and a Streamlit interface to retrieve relevant information from uploaded documents.

🚀 Features
📄 Upload PDF and TXT documents
📝 Extract text from documents
✂️ Split documents into smaller chunks
🔢 Generate text embeddings using Sentence Transformers
🔍 Search relevant document sections using cosine similarity
💬 Ask questions through a chat interface
📚 Display relevant source text
🧠 Basic conversation memory
💾 Cache processed document information
💬 Store conversation history
🖥️ Streamlit web interface

    💡 How It Works

The basic workflow of DocQuery is:

Upload Document
       ↓
Extract Text
       ↓
Split Text into Chunks
       ↓
Generate Embeddings
       ↓
Store Vectors
       ↓
User Asks Question
       ↓
Generate Question Embedding
       ↓
Cosine Similarity Search
       ↓
Find Relevant Chunks
       ↓
Display Answer + Sources
🔍 Example

After uploading a document containing information about Python, you can ask:

Who created Python?

DocQuery searches the document for the most relevant text and returns the matching information.

🧩 Main Components
app.py

Provides the Streamlit user interface.

It handles:

Document upload
Document processing
User questions
Chat messages
Source display
services/loaders.py

Loads supported documents and extracts their text.

services/ingest.py

Processes documents by:

Loading the document
Creating text chunks
Generating embeddings
Adding the data to the vector store
services/embedder.py

Uses the Sentence Transformers model:

all-MiniLM-L6-v2

to convert text into numerical embeddings.

services/vector_store.py

Stores document chunks and their embeddings and performs similarity searches.

services/qa_engine.py

Retrieves relevant document content for a user's question.

services/memory.py

Provides basic conversation history functionality.

services/cache.py

Stores processed document information in the cache.

services/conversations.py

Stores and manages conversation history.

📌 Current Scope

The current implementation primarily uses retrieval and similarity search to find relevant information from uploaded documents.

The retrieved document content is used as the answer rather than being generated by a large language model.
